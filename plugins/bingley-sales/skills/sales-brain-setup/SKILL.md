# AI Sales Brain Setup

If a `LOCAL.md` file sits beside this SKILL.md, read it and let it win over anything here — with one carve-out: the rating strip and licence/attribution notices always stay, whatever a LOCAL.md says.

**Engine dependency:** this skill's deterministic engines run via the bash tool with `python3`. If the session has neither, say so plainly in one line and do only what works without them — never improvise an engine's numbers or renders by hand.

Builds the shared AI sales brain the other skills consume. Everything is written to `sales-os-profile.json` via `scripts/brain_bridge.py` with `source="user"` (strongest precedence — nothing a later skill infers can silently overwrite what the user confirmed here).

## Golden rules
- **Five clickable questions build the brain. Everything after is optional.** Never block. Never force free-text on the required path. Anyone can stop after the questions with a working brain.
- **⛔ COLD-START NEUTRAL.** Never use any name, brand, URL, or fact from the operator's own context, memory files, CLAUDE.md, or prior chats as an option, example, or pre-fill. Options come ONLY from the fixed lists in this spec plus what THIS user has typed in THIS run or their fetched site. Never invent example URLs or businesses. The person running setup is a stranger until they tell you otherwise. **One carve-out — attributed offer, never a pre-fill:** if this working folder's own memory/CLAUDE.md plainly contains the business facts of the person running setup, you may say ONCE, before Q1: *"My notes here say you're [name] and you sell [X] — is that you?"* [That's me] → confirm the noted facts via the 1.6 card (saved `--confirmed` only on "Looks right") and skip the questions they answer. [Not me / start fresh] → the ban applies in full; never mention the notes again. Memory facts NEVER appear inside question options, examples, or unattributed pre-fills — only in that one attributed ask.
- **⛔ OFF-SCRIPT REPLIES.** If the user types instead of tapping: (1) extract any usable answer from the text and save it as if tapped, (2) acknowledge in ≤1 line, (3) move to the NEXT step. Never re-ask a question the text already answered, never repeat the options, never loop. Pure frustration with no answer in it → acknowledge, offer *"Want me to just build it from what I have?"*, and continue.
- **"Just build it" / clear impatience at any point** → stop asking, save what exists, infer the rest (`--source inferred`), jump straight to the final gate.
- **⛔ DOC FAST-PATH.** If the user drops or points at a document at ANY point in the core questions (an ICP doc, positioning doc, pitch deck, one-pager), that beats the questions: read it immediately, extract every core field it answers, and **skip every question the doc already answers** — jump to the first still-empty core field, or straight to the 1.6 confirm card if none remain. Doc-extracted values are pre-fills, not confirmations: they become `--confirmed` only when approved at 1.6 (until then, treat like site-inferred facts). Doc-driven skips do NOT increment `deepSkips`. Say one line: *"Read it — that answers most of this. Two things to check:"* A doc dropped early also satisfies E2 — don't re-ask for materials.
- **Ask with clickable options** (AskUserQuestion), each with a **"Skip — I'll add it later"** escape (NOT "Not sure yet" — that reads as the app being unsure). The skip chip is APPENDED to every core question's fixed list even where the list below doesn't repeat it. The options tool can't dim, fade, disable, or animate — "dim" means omit or reorder options, "disable the field" means ignore a duplicate paste, "progress pill" means one line of status text. Users type their own via the automatic "Other". Never say "firmographics", "persona", or "register" to the user — those are internal words.
- **Cap skips:** on each core-question skip, YOU send `deepSkips=+1` (the bridge applies it atomically; it never increments on its own — send it once per skipped question, never on a retry/replay). After 2 skips, say "Skip two more and I'll be guessing — keep going, or shall I fill the gaps from your website?" (no website known → "…or shall I make my best guess and let you fix it at the end?") — unless the 2nd skip is Q4 (the last question), in which case say "That's the last one — I'll fill the gaps from your website." (no website → "…I'll make my best guess and you can fix it at the end.") A skipped field is inferred from the site, never left empty — and inferred fills MUST be saved with `--source inferred` (they write as skill/Inferred, so a machine guess never masquerades as user-confirmed identity; any later real answer overrides it). **No site to infer from** → seed the skipped field from the nearest Q1/Q1.5 tap (e.g. product = the Q1 category label), saved `--source inferred`, and surface it as an editable row at the final gate. **Exception — `problem` (Q4) has no antecedent tap:** if Q4 is skipped and nothing in the run signals a challenge, leave `problem` EMPTY rather than inventing one — a fabricated challenge would drive a false Finish CTA. An empty `problem` routes to the neutral default CTA (below), phrased as a suggestion, never a diagnosis.
- **Persist every answer + support resume.** Autosave after each answer so a mid-flow bail banks everything so far and can be picked up later. A tab-switcher must never lose their progress.
- **Contradiction card and motion check are CONDITIONAL** and mutually exclusive — fire at most one, only on missing/contradictory signal or a non-outbound business. Never on a clean run. (Distinct from the Step 1.6 "Right?" identity confirm, which is MANDATORY on every run.)
- Base path for all brain writes = `<working folder>/Claude HQ` (same base the other skills use). Never invent a separate store.

## Progress display (dots — on questions AND three milestone cards)
- **Text dots on EVERY question** — prepend a marker to each AskUserQuestion prompt: `●●●○○  Step 3 of 5`. Filled = answered, hollow = remaining. Rides directly above the tappable options. (5 core steps: Q1, Q1.5, Q2, Q3, Q4. Website paste and enrichment steps are NOT in the 5 — they're optional.)
- **Milestone card at THREE points** — render the visual card (via the visual tool) at (1) the kickoff, (2) the checkpoint, and (3) the two-box ending at Finish (ALL-DONE FINAL + WHAT NOW, no dots). Warm card fill (#fff6ef), orange eyebrow pill (fill #f9e3d7, text #c1592f), orange labels/dots (#d97757), dark text, explicit hex (never theme variables). **NO ring, NO star badge, NO left accent bar** — just the eyebrow pill and dots. Kickoff: 5 hollow dots + "Let's build your AI sales brain". Checkpoint: 5 filled + 4 hollow.
- **In the enrichment cards, split the dots into two LABELLED groups** so they teach: the 5 (filled) under a "Your AI sales brain" label, the 4 under a "Making it smarter" label. This shows the user why each part exists and nudges them to continue.
- The card's filled-dot count must match the per-question dots at that moment.
- Always call it the **"AI sales brain"** — never "core brain", "second brain", or just "brain" in anything the user sees.

[No, that's someone else] → do NOT show the stored data, do NOT wipe. Be honest: *"This setup keeps one AI sales brain per working folder, and this one belongs to [name]. To build yours: start me in your own folder, or — if you're taking this machine over — say 'replace it' and I'll archive [name]'s brain and start fresh."* Only an explicit "replace it" archives (rename the profile with an `.archived-<date>` suffix, never delete) and restarts at the kickoff. Ambiguous reply → not confirmed; ask once more, never default to showing another person's data.
   - `seen=true` AND `deepDone=true` → **review path.** Do NOT wipe, do NOT restart at Q1, do NOT re-render the kickoff. If `website=` was saved but Step 1.6 never confirmed, re-fire the fetch on resume; if `website` is unset and no "[I don't have a website]" answer was recorded, offer the website paste right after the resumed question.
2. Set `seen=true` on first run.
3. **Kickoff (mandatory, before Q1):** render the kickoff card AND say this intro with it (one message): *"I'm going to ask 5 quick tap-to-answer questions — a couple of minutes — to build your AI sales brain: the profile every sales skill here reads, so emails, lists and research already know your business. Skip anything; nothing is sent anywhere."* Never open with a bare question.

## STEP 1 — the questions (AskUserQuestion, one screen each, branching)

**⛔ OPTION FLOOR — AskUserQuestion requires a MINIMUM of 2 options per question** (the tool errors below 2). A follow-up whose only natural chip is "Skip" (e.g. E1's "who's NOT a fit") must pair it with one substantive example chip — never send a lone Skip. **⛔ OPTION CAP — AskUserQuestion renders a MAXIMUM of 4 options per screen** (and always adds its own "Other" free-type on top; longer lists can't render). Every question screen shows at most 4 chips INCLUDING the "Skip — I'll add it later" chip — so 3 substantive options + Skip. Pick the 3 most likely given prior answers: Q1 defaults to **Service I deliver · Software / SaaS · Done-for-you agency**; Q2 and Q4 pick the 3 best-fit options for the user's lens/product from the FIXED lists below — never invent new option text. Mention in the question line that they can type their own answer (that's the built-in "Other"). The full fixed lists below stay in the spec as the POOL to draw from — never all on screen at once, and any "dim / additive reveal / collapse" wording below means choosing WHICH 3 to surface, not showing more than 4.

**Q1 — What do you sell?** options: Service I deliver · Done-for-you agency · Software / SaaS · Coaching or info product · Digital product / templates · Newsletter or media brand · Physical product · Reseller / distributor · Local trade or service. (multi-select ok; if Physical/Reseller, sub-ask exactly: *"Do you make it, resell it, or distribute for someone else?"*) **Multi-business fork here:** if they run more than one, ask *"Which one should we set up first? (The one you're actively selling.)"* — save the others to `wcNotes="other businesses: X, Y"`, scope EVERY later step (website, Q2–Q4, confirm) to the chosen business only, and at Finish be honest: *"Your AI sales brain covers [A] for now — when you want to switch focus to [B], say 'switch my AI sales brain to [B]' and we'll rebuild it."* Build ONE brain cleanly, never blend two.
→ save `product=` (category seed; the detailed version comes from the website confirm)

**Q1.5 — Do you sell to businesses or people?** options: Businesses (B2B) · People (B2C) · Both.
→ save `lens=B2B` or `lens=B2C` (Both → B2B default, note the B2C side in audience).

## STEP 1.4 — Website, pasted early and fetched in the BACKGROUND (biggest lever)
Right after Q1.5: "Paste your website and I'll fold it in as we go — or skip." Options: **[I don't have a website] · [Skip — I'll add it later]**; the URL comes via the automatic "Other" free-type. **Never offer an example URL as an option** — if you show a placeholder anywhere, it is exactly `yourcompany.com`, nothing else. On paste:
- **Fire the fetch immediately and NON-BLOCKING.** The user keeps answering Q2-Q4 while it runs. Show a live progress pill, never a bare spinner: *"Reading your site → checking your socials → a quick web search…"*.
- The fetch: site + follow its links to socials (LinkedIn, X, etc.) + a quick web search on the business name for case studies / press / reviews.
- Disable the field on submit and ignore refires of the same URL (double-fire guard).
- By the time they finish Q4, the identity + product confirm (Step 1.6) and the inferred facts are already populated → near-zero perceived wait.
- **Timeout:** if the fetch hasn't returned by the time they reach Step 1.6 (or ~15s), treat it as failed and drop to the free-text fallback — never leave them staring at a stuck pill.
- **Failed/timed-out fetch is never silent:** say one line — *"Couldn't read your site just now — no problem, two quick lines instead."* Save `website=` (the URL) but do NOT set `site=true` (that flag means a successful fetch only). Partial fetch (site ok, socials/search failed) → use what returned, no message. Obvious URL typo → offer ONE corrected retry, then fall back.
- No website / fetch fails → route the product capture to the free-text fallback in Step 1.6.

**Q2 — Who's your ideal customer?** Base options (FIXED — never improvise this list): Small local businesses · Online businesses / e-commerce · Startups and tech companies · Larger companies (500+ staff) · Agencies and consultancies · Individual consumers · Professionals (e.g. lawyers, dentists) · Skip — I'll add it later. Adapt to Q1+Q1.5 by **additive reveal, not reshuffle** — keep positions stable, dim the irrelevant (B2C → dim the company chips; B2B → dim Individual consumers), fade in the newly-relevant below with a "based on your last answer" tag. Collapse the enterprise-detail / marketplace-two-audience extras behind one tappable "Sell to big companies, or through a platform like Amazon? +".
- **Capture the buy-side, not just a vibe (this is what makes lists good).** For B2B, the `audience` you save should carry, where the tap/site/other give it: the **buyer's job title/persona** (e.g. "Heads of RevOps"), the **company profile** (size band, industry, geo). Pull these from the website + Q1/Q1.5 automatically; only ask a short follow-up if they're missing and the user is B2B — e.g. a one-tap "Who's your buyer? [Founder/CEO · VP/Head of dept · Manager · Practitioner]" and, if useful, "Company size? [<50 · 50–500 · 500+]". Keep it optional and fast; never a wall. The richer `audience` string flows into the confirm card's "Who you sell to" row.
→ save `audience=` (weave in title + firmographics when known)

**Q3 — What's your role?** options: Founder / owner · Sales or BD · Marketing · Agency owner · Freelancer / solo · Agent / rep · Consultant.
→ save `register=` hint (founder/owner → direct; consultant → considered; any other role → `considered` by default).

**Q4 — Biggest challenge right now? (last question)** options with FIXED hints (never improvise or "tune" them): Not enough leads (*"e.g. the diary's empty next month"*) · Not getting replies (*"e.g. 100 emails out, nothing back"*) · Struggling to close (*"e.g. good calls, no signatures"*) · No time for outreach (*"e.g. delivery eats the week"*) · Don't know who to target (*"e.g. everyone's a maybe"*) · Deals drag on too long (*"e.g. months of chasing sign-off"*) · Win back old customers (*"e.g. past buyers gone quiet"*) · Skip — I'll add it later.
→ save `problem=`
- **This is the final core question.** Don't ask what the user wants AI to do first — most new users don't know yet, and it adds friction. Instead, *derive* the first move from their challenge and save it SILENTLY as `ask=` at Finish (mapping below) — downstream skills read it; the close never pitches it.

## STEP 1.6 — "Right?" confirm (plain words, doubles as identity check)
**SEQUENCE (no-website / failed-fetch path):** collect the free-text pitch line AND the trading name (fallbacks below) BEFORE any confirm card. **The card renders ONLY with ≥2 real rows.** Below that, replace it with one plain line — *"So: you're **[name]**, and you sell **[pitch]** — right? [Looks right / Edit]"* — never render a card with 0–1 rows. An empty "Here's what I've got" is a bug, not a card. **Inferred/guessed values DO count toward this ≥2 threshold** — render them in the card marked "(my guess — tap Edit to fix)" so the user can correct them; fall to the plain line only when fewer than 2 rows exist even counting inferred fills.
Using the backgrounded fetch, show ONE card with the facts in plain sales language — NOT "benefit/proof/differentiator", the user never sees those words. Each row is ONE plain line; where a benefit or wedge was found, weave it into that same line's wording (don't add a second sub-line or a separate row):
- **What you sell** → business.product, enriched with business.benefit in the same sentence
- **Who you sell to** → business.audience (the buyer + company profile from Q2/site). Confirming the BUY-side here, not just the sell-side, is what lets a seller catch a wrong target before it wrecks their first list. Show it whenever audience is known.
- **Why people pick you** → business.differentiator, enriched with wedge in the same sentence
- **Who you've helped** → business.proof
Headline: ALWAYS exactly **"Here's what I've got — right?"** — the company name lives ONLY in the eyebrow pill, never in the headline (a name in the 22px headline overflows the card). **Long name?** No length rule needed — the card template truncates the pill with an ellipsis, so even a very long company name stays a proper eyebrow and can never dominate the card; if no name surfaced at all, use the fixed **"QUICK CHECK"** pill. Chips: [Looks right] · [Edit] · [Not us].
- Show ONLY the rows actually found — never an empty row.
- **This is the identity gate — you MUST get an explicit "Looks right" before moving on.** Never treat an ambiguous reply as approval.
- **[Edit] flow:** ask which line to change (What you sell / Who you sell to / Why people pick you / Who you've helped — every row on the card is editable, especially the buy-side), take their words for that line, then **RE-SHOW the updated card and ask again** [Looks right / Edit another]. Loop until they pick "Looks right". Only then save and continue.
- **Clear textual affirmatives COUNT as "Looks right"** — "yes", "fine", "looks right", "correct", "yep" typed in free text approve the card; don't force the chip. Only genuinely ambiguous edit-scope replies ("all of it", "hmm") get ONE disambiguation — *"Do you want to reword any of these, or are they fine as they are?"* — and if still ambiguous, treat as approved and move on. Never loop.
- [Not us] → "Paste the exact URL, or tell me the name" — never dead-end.
- **"Who you've helped" missing?** one optional line anyone can answer: *"Who's a customer you're proud of? A name, a win, or 'we helped X do Y.' One line's plenty."* Placeholder: *"e.g. Helped a local gym double sign-ups in 3 months"*. Skippable.
- **No website:** free-text fallback — *"In a line, what do you sell and why do people buy?"* with tappable suggestions from Q1. Only time it's a blank box. **Never leave `name=` null:** if no company name surfaced, add one short line — *"And what do you trade as? (Your own name is fine.)"* — a solo freelancer's first name is a valid answer. Downstream skills print "Scoring as **[name]**", so an empty name breaks that line.
→ save `name=` (the company name — never leave it null when known), `product=`, `audience=`, `benefit=`, `differentiator=`, `proof=`, `wedge=`, `website=`; set `site=true` ONLY if the fetch actually succeeded

## Conditional contradiction card / motion check
(Naming: the mandatory Step 1.6 "Right?" card is the IDENTITY confirm; this section's card is the CONTRADICTION card. Different cards.)
Decidable triggers (never improvise):
- **Contradiction card** fires ONLY on a real contradiction or genuinely low confidence — e.g. the Q1 tap says SaaS but the site reads consulting, or the fetch found so little that product/audience are guesses. Copy (fixed): headline *"One thing doesn't line up"*, line *"You tapped **[Q1 answer]**, but your site reads more like **[site reading]**. Which is closer to what you actually sell?"*, chips [The first one] · [The second one] · [Bit of both — let me put it in my words]. Save the winner as `product=` (`--confirmed`).
- **Motion check** fires ONLY for a non-outbound / off-domain business — e.g. a pure DTC shop with no prospecting motion. Copy (fixed): headline *"Quick check — how do you sell?"*, line *"Looks like customers come to you rather than you chasing them. Do you ever reach out cold — to stockists, partners, or past customers?"*, chips [Yes, sometimes] · [No — they find us]. Save to `wcNotes="motion: inbound"` or `"motion: outbound"`; use it to pick the Finish CTA.
- **Precedence:** fire at most ONE — contradiction beats motion. And if the Step 1.6 identity card already surfaced the conflict (the user saw and resolved it there), NEITHER fires — 1.6 subsumes both. Never on a clean run.

## STEP 2 — The 4 optional extras, ONE AT A TIME (targeting first — it makes lists tight)
**⛔ RENDER CHECKLIST (mandatory, every run that enters the extras):** checkpoint card BEFORE E1 · the "STEP n OF 4" card BEFORE each E question, second dot-group advanced to match · final summary card BEFORE the gate · the two-box ending (ALL-DONE FINAL + WHAT NOW, one render) at Finish (never end on the summary card). If a card on this list wasn't rendered, the step didn't happen — render it before asking. **A skipped extra still fills its dot** — dots track position, not completion; the pill and dots advance monotonically.
Keep every card lean: headline (≤6 words) + one short line + chips. No paragraphs. When asking for materials, offer EXAMPLES as ideas, never a demand — the user may not have any given one, so list a spread and let them drop whatever they've got.

**E1 — Sharpen your targeting (list-quality lever; a few taps, skippable).** The 5 core questions capture what you sell; this captures *exactly who you email*, which is what makes a prospect list tight instead of vague. Optional and fast — never a wall, and B2C users who don't prospect by title can skip.
- Headline: **"Sharpen your targeting"**
- Line: **"Who is your ideal customer? The more I know, the sharper every response."**
- **⛔ NEVER re-ask what Q2 answered.** Open by quoting it back: *"You said you sell to **[Q2 answer]** — want to sharpen that to an exact title, size and region, or is that tight enough?"* (Q2 skipped/inferred → *"Looks like you sell to **[X]** —"* instead of "You said".) Chips: [Sharpen it] · [That's tight — skip] — these ARE E1's chips; [Sharpen it] leads into the capture taps below. Only ask for the fields the quote-back doesn't already contain.
- Capture in quick taps + optional free-text (pre-filled from Q2/site so it's usually one confirm, not typing):
  - **Who's the buyer? (their job title)** — one-tap [Founder/CEO · VP/Head of dept · Manager · Practitioner] or type the exact title ("Head of Sales").
  - **Company size** — [<50 · 50–500 · 500+].
  - **Industry / region** — free-text, pre-filled from the site ("UK fintech", "US e-commerce").
  - Optional: **who's NOT a fit** (a one-line disqualifier — "too small / no in-house team"). Powers list filtering.
- Weave into `audience=` (source="user") so it enriches the "Who you sell to" line and every downstream list. Disqualifier → `wcNotes=` (working context).

**E2 — Add your sales materials (richest input for HOW you sell, zero setup).** File upload works right now; a real sales deck/pitch beats the website's marketing gloss. **Be precise about WHICH assets** — "your best stuff"/"materials" is too vague; name the actual sales documents an AE would recognise so they know exactly what to grab.
- Headline: **"Add your sales materials"**
- Line: **"Have a sales deck, a case study, or a proposal you send prospects? Drop it in and I'll learn how you pitch."**
- Name the concrete assets (list, not a demand): *your sales deck or pitch deck · a case study or customer win · a one-pager about what you do · a proposal that won the deal · screenshots of a few emails that got replies · a testimonial*. Framing: "Got any of these? Drag them in. If not, skip — the website already gave me the basics." (Winning emails are the single best input for cold-email output and the easiest to grab — surface them.)
- Chips: [Upload a file] · [Skip]
- Read the files, extract into `benefit`/`proof`/`differentiator`/`wedge` (and voice cues); confirm anything material as editable.
- **"My notes are in Notion / Obsidian / a wiki":** never claim you can read it unless a connector is live. Notion → offer the Notion connector (E4 rules apply: verify-read before claiming success, ask which page/database holds the business facts). Anything else (Obsidian, local vaults, no connector) → *"Easiest: export or copy the page about your business — what you sell, who you sell to — and drop it here."* A dropped export is treated exactly like any E2 file. Never dead-end, never fake a read.

**E3 — Write in your voice.** Headline: **"Write in your voice"**, line: **"Paste a few emails you've sent, or connect your email — so everything I write sounds like you."** Chips: [Paste emails] · [Connect email] · [Skip]. **Paste is first and equal — never push connect over paste** (a user who's owned the tool for four minutes would rather paste than hand over their inbox). "Connect email" works for **Gmail today**; if they're on **Outlook, be honest** — *"I can't auto-connect Outlook yet, but paste a few sent emails and I'll learn your voice the same way"* — and route to Paste. Never offer an Outlook connect you can't complete. Follow the connect rules in "Connecting email or a CRM" below. Pasted samples **append** to `<wf>/Claude HQ/voice/corpus/emails.txt` (create the `voice/corpus/` dir and `emails.txt` if absent; append behind a dated separator line, e.g. `--- pasted 2026-07-02 ---`, never overwrite); save `profileRef="voice/voice_profile.md"` (the register selector file, not the raw samples — if `voice_profile.md` doesn't exist yet for this user, still set `profileRef` to that path and note in the recap that the voice skill builds it from the corpus) and `register=` from tone, with flags per the exact "Flag semantics" rules below (paste → `sentMailVoice=true`; verified Gmail read → both `gmail=true` and `sentMailVoice=true`).

**E4 — Connect your CRM (optional tail, demoted).** CRM is heavier (per-tool auth) and tells the brain who they talk to, not how they sell — so it's LAST and clearly optional. Headline: **"Connect your CRM"**, line: **"So I never suggest people you're already talking to — and I know who your customers are. Optional; skip if you don't use one."** Chips: [Connect] · [Skip].

**E4 decision tree (follow exactly):**
1. **Ask which CRM.** Chips: HubSpot · Salesforce · Pipedrive · Spreadsheet / none (type others via "Other").
2. **Named CRM → try to connect it directly; an empty registry result is NOT proof there's no connector.** Many CRMs ship as **plugin** connectors that `search_mcp_registry` does not reliably list (HubSpot, Close, Zoho, Attio, Salesforce, Monday, Notion, Airtable and more). So: if a connector/tool for the named CRM is available in this session (or you can search deferred tools for it), go STRAIGHT to connect + verify-read (step 3). Only fall to the CSV fallback (step 4) when there is genuinely no connector — never let one empty `search_mcp_registry` result alone route a well-known CRM to CSV. (You may still search the registry for obscure CRMs; retry once on an empty result.)
3. **Connector found / available** (HubSpot, Close, Zoho, Attio connect directly; Monday, Notion, Airtable need one extra tap — *"Which board/database/base is your CRM?"*): run the connect, verify-read, flags per Flag semantics. Success → say what you can see (*"Connected — I can see your companies and deals."*).
4. **No connector** (Salesforce, Dynamics, Pipedrive, anything obscure/vertical) → **CSV export is the universal fallback, offer it by name:** *"No auto-connect for [X] yet — but every CRM exports a CSV. Export your accounts or contacts and drop the file here; I'll fold them in so lists skip your pipeline. Or skip — I'll still work from your website and materials."* On drop: read it, store at `<wf>/Claude HQ/crm/pipeline-accounts.csv`, append `wcNotes="crm: [X]; pipeline CSV imported <date>, N accounts"`. **Do NOT set `callNotes`** — that flag means a verified live read only.
5. **Spreadsheet-as-CRM** → same as 4 minus the apology: *"Drop the file in."*
6. **"My inbox is my CRM"** → *"Then there's nothing to connect here — the voice step already covers your email."* Skip, no flags.

Only set `callNotes=true` **after** a real read confirms the connection. NOT Apollo/Instantly (those act — they live in the doing-skills).

## Connecting email or a CRM — how to actually do it (governs E2-connect and E3-connect)
Most new users have never connected a tool and will freeze or bail if it's vague or scary. Walk them through it, honestly, and NEVER fake it.
- **Say what happens, in one line, before you start:** *"A secure window opens, you approve access, and that's it — takes about 20 seconds. I only read; I never send anything without asking."*
- **Trigger the actual connector** for the tool they named (the email or CRM MCP). Do not describe a connection you haven't started.
- **Verify before you claim success.** After the connector reports authorised, make ONE tiny real read (e.g. list a few recent sent emails / fetch a couple of account names). Only then say it's connected — and say **what you can now see**: *"Connected. I can see your last 20 sent emails"* / *"Connected — I can see 340 accounts and their contacts."* If the read returns nothing, say so and offer the fallback; don't pretend.
- **Flag semantics (exact — never guess):**
  - Gmail, successful read → set BOTH `gmail=true` AND `sentMailVoice=true`.
  - Gmail, auth ok but EMPTY read → set `gmail=true` only, say *"Connected, but I found no sent mail — paste a few emails instead and I'll learn your voice that way,"* and route to Paste (`sentMailVoice=true` only once samples exist).
  - Errored read (auth ok, read throws) → set NO flags at all.
  - Pasted samples (no connect) → `sentMailVoice=true` only.
  - CRM, successful read → `callNotes=true`; anything less → nothing.
- **An errored read is NOT a connection.** If the read itself fails or throws (not just returns empty), treat the connection as NOT established — do not say "connected," set no flags. Fall back exactly as "If it can't complete" below. (Auth succeeding is not proof; only a successful read is.)
- **If it can't complete** (connector unavailable, auth cancelled, times out, or — for Outlook — no connector yet): don't dead-end. *"Couldn't finish connecting [tool] just now. Two easy options: paste a few emails instead, or skip and connect later from settings — nothing's lost."* Then continue the flow. **You cannot see the approval window**, so use this observable loop instead: attempt the verify-read; if it fails with an auth-pending/unauthorised error, ask once *"Done approving in the window?"* and retry on yes; if it still fails, the user says they cancelled, or ~60 seconds pass with no result, fall back as above. Never loop more than one retry.
- **If they have questions, answer plainly, then continue** (don't loop):
  - *"Is it safe?"* → *"Yes — read-only access, and you can disconnect anytime in settings."*
  - *"What will you see?"* → *"Just your sent emails, to learn your tone"* / *"Your accounts and contacts, so I know who you deal with."*
  - *"Do I have to?"* → *"Not at all — skip it and paste later, everything still works."*
  - *"Not sure which email I use?"* → *"If you sign in with a Google/Gmail account it's Gmail. If it's @outlook/@hotmail or Office 365, we'll paste instead. Easiest: just paste 3 emails you've sent and we're done."*
  - *"Not sure if I even have a CRM?"* → *"If you're not sure, you probably don't need to connect one now — skip it, everything still works."*
- **Skipping or falling back on a connect step (E2/E3) does NOT increment `deepSkips`** — the skip cap counts only the 5 core questions, so a failed connect never triggers the skip-cap nag.
- **Never claim "connected and noted" or similar unless a real read succeeded.** A false confirmation is worse than skipping.

**One-tap bonus (decidable trigger — offer exactly once, immediately after the first COMPLETED (non-skipped) extra; if all extras are skipped, never offer it):** deal size + who signs off — *"Roughly your deal size? [Under £1k · £1–10k · £10k+]"* and *"Who signs off? [Owner · Manager · Committee]"*. Shapes tone/urgency of everything the brain writes. Offer once; skip freely. **Save mapping (exact):** deal size taps map to the A/B enum, never the literal £ label — Under £1k or £1–10k → `dealSizeProfile=A`, £10k+ → `dealSizeProfile=B`. Who-signs-off has no dedicated field — fold it into `wcNotes=` (e.g. `wcNotes="sign-off: committee"`). **Timing:** fire it right after that first completed extra's save, BEFORE you render the next extra's card — never mid-card.

### Weighting (the key rule)
- **Tier A — setup-confirmed identity** (company, product, audience, lens): authoritative, saved `source="user"`. Background may *flag* a conflict but must NEVER silently overwrite it.
- **Tier B — working context** (current campaigns, target accounts, live offers, objections, recent wins): first-class and recency-weighted — this is what "hones in" on the user. Write to its own `workingContext.*` keys (schema tolerates unknown keys), so it never fights Tier-A identity. Downstream skills read it for current focus.
- **Tier C — passive mentions:** stored low-weight, promoted later. Over-collection is fine.
Precedence is already enforced by brainstore (user=3 > skill/inferred=1), so background writes as `source="skill"` enrich but cannot clobber Tier-A. Tier B avoids conflict by living in new keys.

## Card specs — ONE HTML template, the browser does the layout
All cards are **HTML rendered via the visual tool**, not hand-authored SVG. The browser sizes everything: the eyebrow pill is exactly as wide as its text, long values wrap on their own, card height is automatic. **You NEVER compute a pill width, an x-coordinate, a viewBox, a dot position, or a wrap point** — you supply DATA, the template renders it. This is deliberate: it makes pill-overflow, text running off the card, and mis-spaced dots structurally impossible instead of caveated.

**How to render a card:** paste the template below verbatim into the visual tool, set the `CARD` object, done. Two families share it: `renderCard` (rows cards — the confirm, the ALL-DONE FINAL and the WHAT NOW) and `renderMilestone` (the position cards — kickoff, checkpoint, enrichment).

Design tokens (unchanged): warm fill `#fff6ef`, border `#f2ddcf`, eyebrow pill fill `#f9e3d7` / text `#c1592f`, orange labels + dots `#d97757`, dark text `#2b2320`, muted sub-text `#7a6f68`. **NO ring, NO star badge, NO left accent bar** — just the pill and dots. Headline size is the only two-tier bit and the template handles it from `family`: milestone cards = 26, working cards (confirm/summary/enrichment) = 22.

```html
<div id="card" style="padding:8px 0;font-family:-apple-system,'Segoe UI',sans-serif"></div>
<script>
function dot(f){return '<span style="display:inline-block;width:12px;height:12px;border-radius:50%;'+(f?'background:#d97757':'border:1.5px solid #d97757;box-sizing:border-box')+'"></span>';}
function grp(g){var d=g.dots.map(dot).join('');var l=g.label?'<div style="font-size:11px;letter-spacing:1px;font-weight:600;color:#d97757;text-transform:uppercase;margin-bottom:9px">'+g.label+'</div>':'';return '<div>'+l+'<div style="display:flex;gap:14px">'+d+'</div></div>';}
function shell(x){return '<div style="background:#fff6ef;border:1px solid #f2ddcf;border-radius:18px;padding:24px 36px 28px">'+x+'</div>';}
function pill(t){return '<span style="display:inline-block;max-width:300px;overflow:hidden;text-overflow:ellipsis;white-space:nowrap;vertical-align:bottom;background:#f9e3d7;color:#c1592f;font-size:12px;letter-spacing:1.2px;font-weight:600;text-transform:uppercase;padding:5px 12px;border-radius:11px">'+t+'</span>';}
function head(t,fam){return '<div style="font-size:'+(fam==='milestone'?26:22)+'px;font-weight:700;color:#2b2320;margin:16px 0 6px">'+t+'</div>';}
function renderMilestone(d){
  var lines=(d.lines||[]).map(function(l){return '<div style="font-size:14px;color:#7a6f68;line-height:1.5">'+l+'</div>';}).join('');
  var pull=d.pullLine?'<div style="font-size:16px;font-weight:600;color:#d97757;margin:10px 0 8px">'+d.pullLine+'</div>':'';

function renderCard(d){

  }).join('');
  return shell(pill(d.pill)+head(d.headline,d.family||'working')+sub+rows);
}
function renderStack(cards){return cards.map(function(c){return '<div style="margin-bottom:14px">'+(c.kind==='card'?renderCard(c):renderMilestone(c))+'</div>';}).join('');}
/* ==== SET ONLY THIS PER RENDER (examples in the data table below), leave the rest ==== */
var CARD = {

  headline:"Let’s build your AI sales brain",

</script>
```

Dots are just `true` (filled) / `false` (hollow) arrays. **Two independent knobs:** `kind` picks the RENDERER — `"card"` → `renderCard` (rows, no dots: confirm, summary, ALL-DONE FINAL, WHAT NOW), anything else → `renderMilestone` (dots: kickoff, checkpoint, enrichment). `family` independently picks HEADLINE SIZE — `"milestone"` → 26px, anything else → 22px.
